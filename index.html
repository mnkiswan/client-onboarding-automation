The problem

Every new client meant the same manual admin

Intake details came in by email and call, in different formats, and someone re-typed them into the CRM, wrote a welcome document, and created the same kickoff tasks each time.

How it works

From trigger to finished work

Trigger: a new form entry is submitted (real-time).

01

Intake form submitted

A client fills in one standard Zoho Forms form. Every client gives the same information.

02

Create the account in CRM

Zoho CRM gets the account record, then the contact is created or updated.

03

Create a deal

A deal is created so the sales pipeline reflects the new client straight away.

04

Merge and email the welcome document

Zoho Writer fills a template with the client's details and the document is emailed.

05

Create the Zoho Projects task list

A task list and its tasks or subtasks are created so the delivery team starts work immediately.

Decision: the flow routes by client segment (Enterprise, Group or Default). Each route creates its own set of tasks.
Error handling: failures on the CRM steps go to an 'Error alert task' branch, so a broken run shows up instead of disappearing.
Why it matters for the business

What changes when this runs

Same experience for every client

Each client gets the same records, welcome document and first tasks, so the first impression does not depend on who handled intake.

No re-typing

Intake data moves from the form to CRM, document and tasks once. That removes copy errors.

Faster start

Delivery work begins as soon as the form is submitted, not after someone has time to set it up.

Failures are visible

The error branch means a broken step is caught and reported, which is why the 1 failed run is documented.
